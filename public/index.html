Help

What is shellnote?

A local notebook for runnable Markdown notes. Notes are plain .md files; every fenced code block tagged powershell, cmd, bash, or gitbash becomes a cell you can run with one click. The server binds to 127.0.0.1 only — nothing is reachable from the network.

Editing notes

Text renders as regular Markdown. Edit a section with the pencil in its hover gutter (or double-click it); hover between sections for a + insert line. The <> toggle in the header switches to a raw Markdown editor for the whole note. Files edited outside the app are picked up on reload.

Supported: headings, bold/italic/strikethrough (** or __), inline code, links and images, bullet and numbered lists including nested ones, task lists (- [ ], shown as read-only checkboxes — tick them by editing the text), blockquotes, horizontal rules, tables with alignment, and code fences (shell tags become runnable blocks, others display as code). Not supported: footnotes, reference links, bare-URL autolinking, and raw HTML, which is escaped rather than rendered.

Organising the sidebar

Drag notes to arrange them, or use the sort button to restore A–Z (it's greyed out when the list already is). Hover a note and click its star to add it to Quick access, a collapsible section pinned above the list. Both the arrangement and the Quick access set are remembered per notes folder.

Where blocks run

Each block's header shows the folder it will run in. The starting folder is the Run folder (Settings), defaulting to where the server was started. A cd inside a block shifts the folder of same-shell blocks below it — each shell keeps its own folder lineage, and only forms that shell understands are recognized (cd /d, bare D: for cmd; Set-Location for powershell; case-sensitive cd and ~ for bash). Targets built from environment variables can't be predicted and are ignored.

Interactive input

While a block runs, an input row appears under its output — type a response and press Enter to send it to the process (read, Read-Host, set /p, y/n prompts). End input closes stdin for commands that read until end-of-input.

Full-screen terminal programs (vim, htop, arrow-key menus) are not supported — the output view is plain text, not a terminal emulator. Note that sent input is echoed into the output and stored in the run log; avoid typing secrets.

Processes

The Processes tab lists every run across all notes — running and recent — with live status, duration, View (pop-out window, which also accepts input), Kill, and Remove. History survives server restarts.

Each row has a Comment you can write on to remember what a run was for. Double-click the cell (or the pencil that appears on hover) to edit it, Enter to save, Esc to cancel; long text is truncated and shown in full on hover. Comments are kept with the run's history and disappear when it's removed.

Reading a log (pop-out)

A block's own output stays a plain scrolling transcript. Pop out — from a block header or the Processes tab — opens the same run in a log viewer built for longer output, live or finished. Highlights and bookmarks only ever add a background or a margin marker: the log's own text is never recoloured or rewritten.

Search the log as plain text or a regular expression (.*), with Aa for case, ‹ › to step through hits (Enter / Shift+Enter), and Only matches to hide everything else. Ctrl+F jumps to the box, Esc clears it.

Highlights colour the background of any line containing one of their keywords — edit them in Settings, or per-run from the pop-out's own Settings button.

Bookmarks — hover any line and a hollow bookmark icon appears at its left edge. Click it to bookmark the line in the default colour, or hover it to expand five colours plus a comment box; clicking a filled icon removes the bookmark. A bookmarked line keeps that icon, in its colour, in the left gutter. A commented line shows its note on hover, and on the ruler mark's tooltip. Bookmarks and comments save themselves and reappear next time you open that run.

The right-hand ruler replaces the scrollbar: every highlighted line is a coloured bar and every bookmark a fixed-size mark, so a 20,000-line run reads at a glance. Click to jump, drag to scrub, hover to widen it — the bookmark marks keep their size so they don't shift under the pointer.

The panel appears when you hover the top-right corner: each highlight with its count, clicking one hides those lines, plus Other lines for everything neither highlighted nor bookmarked and All / None to flip the whole set. Bookmark colours are listed below with their own counts and toggles.

Following stops as soon as you scroll up or step through matches; Jump to latest resumes it. Markup controls the highlight backgrounds only — the bookmark icons and the ruler keep working with it off — and starts off until this log's highlights have been configured. # shows line numbers (kept out of copied text), Wrap switches between wrapping and a horizontal scroll, Copy / Save take whatever the filters leave visible, and the button at the far left of the header hides the toolbar.

Log highlights

Settings → Log highlights defines the keyword highlights the log viewer uses. A line containing one of a highlight's keywords gets that highlight's background colour — the log's own text is never recoloured, so nothing a command actually printed is misrepresented.

Pick a highlight from the list to edit it on the right: its name, colour, keywords (added and removed one chip at a time), and whether it must match whole words (so pass doesn't match password) or an exact case. The preview shows a matching line as it will actually look in the log.

A dot beside a highlight means it differs from the built-in default; anything without one keeps following the defaults rather than being frozen as a copy. Reset to defaults clears the lot. The Colour theme sets how strong the colours are: Friendly is soft pastel, High contrast is stronger and more saturated.

Everything in this dialog is global. Settings in the pop-out toolbar opens the same editor with an Applies to choice per highlight — this log only, this note, or everywhere. A line only ever gets one highlight, and the narrower scope wins, so a rule added for a single run beats a broad global one like error.

Shells & platforms

cmd and gitbash blocks run on Windows only (git-bash must be installed). bash uses /bin/bash on macOS/Linux and git-bash on Windows. powershell uses powershell.exe on Windows and pwsh elsewhere. Blocks are otherwise stateless — environment variables don't carry between blocks.

Your data

Notes live in your notes folder (sidebar). Settings and run logs live in the app data folder — both are shown and changeable in Settings.
